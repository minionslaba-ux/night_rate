# Аккаунты и сохранения (Supabase)

Логины, пароли и прогресс игроков хранятся в отдельном проекте Supabase **night-fare** (регион eu-central-1, Франкфурт).
Он не пересекается с проектом другой игры.

## Как это устроено

- **Пароли** хранит Supabase Auth (bcrypt). Ни игра, ни таблицы их не видят.
- **Вход только через Telegram, ВКонтакте или MAX** (функция `nf-login`), с v48. Логина и пароля нет: `nf-register` отключена и отвечает 410, формы в игре убраны. Перед отключением проверили: профилей без привязки к Telegram, ВК или MAX не было.
- На другом устройстве можно войти по 8-значному коду («Получить код для другого устройства» в профиле).
- **Профиль** — таблица `public.profiles`:

| Поле | Что в нём |
| --- | --- |
| `id` | id пользователя Supabase Auth |
| `login` | логин, уникальный, меняет только сервер |
| `name` | имя в игре |
| `data` | монеты, гараж, покраска, неон, костюмы, прокачка, расходники, достижения, статистика |
| `progress` | до какой миссии дошёл в каждом эпизоде, последняя миссия (для кнопки «Продолжить») |
| `is_tester` | тестовый режим: бессмертие и бесплатные покупки. Меняется только SQL-запросом разработчика |

- **Защита строк (RLS):** игрок читает и меняет только свою строку. Право на `update` дано только на колонки `name`, `data`, `progress`, так что `login` и `is_tester` из игры не поменять.
- **Сессия** запоминается в браузере (supabase-js), повторно входить не нужно. Прогресс отправляется на сервер через 2,5 секунды после изменения и при закрытии страницы.
- **Гость** играет без аккаунта, прогресс хранится только в этом браузере.

В игре лежат только адрес проекта и публикуемый ключ (`sb_publishable_…`). Они рассчитаны на то, чтобы быть в клиенте: доступ ограничивают правила RLS.

## Площадки и коды

Вход через Telegram, ВК и MAX, коды для входа с другого устройства и удаление аккаунта — функция `nf-login`. Таблицы `tg_accounts`, `vk_accounts`, `max_accounts` и `link_codes` доступны только серверу. Подробности и шаги настройки — в [platforms.md](platforms.md).

## Защита прогресса

При входе игра сравнивает прогресс гостя на этом устройстве с прогрессом на сервере:
- **на сервере пусто:** прогресс гостя переносится в профиль;
- **прогресс есть и там, и там:** игрок сам выбирает, что оставить.

Пока выбор не сделан, игра ничего не отправляет на сервер.

## Ошибки игроков

Таблица `client_errors`: версия, площадка, браузер, текст ошибки. Записывать в неё может любой, читать из игры нельзя.

## Тестовый профиль

Логин `тест`, флаг `is_tester = true`. Бессмертие теперь включается только по флагу с сервера: через консоль браузера или подменой локальных данных его не получить.
Выключить перед релизом:

```sql
update public.profiles set is_tester = false where login = 'тест';
```

## Что стоит сделать дальше

- Монеты и покупки пока считает игра на стороне игрока, поэтому их можно подделать в своём профиле. Для настоящих платежей покупки надо проверять на сервере: Edge Function и чеки платёжного SDK площадки.
- Ограничить частоту регистраций (защита от ботов), например капчей Supabase.
